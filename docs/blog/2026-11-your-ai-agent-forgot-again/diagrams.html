What the model actually sees

Everything an agent “knows” in a session is text in one context window. Nothing else.

System promptwritten by the app: who it is, how to use tools, safety rules
Tool definitionsnames, descriptions and inputs of every tool, including each MCP server's tools
Instruction files: AGENTS.md · CLAUDE.md · skillsyour project's rules, loaded at session start. The only “memory” most agents have
Your requestthe task you typed
Conversation + tool results (grows every step)commands and their output, files read, edits, errors… until the window fills up. Then the app compacts: old steps are summarized or dropped

When the session ends, this window is thrown away. The next session starts from the system prompt and your instruction files again.

Agents propose. People decide.

The line Agentsol never lets an agent cross.

What an agent can do (MCP tools, hooks)

  • Read the project's instruction files, with secrets masked
  • Run checks, get the briefing, check a command
  • Review its own past sessions
  • Record findings and propose a change as a diff

What only a person can do (CLI, real terminal)

  • Register a project
  • Review the exact diff
  • Approve with a one-time code. Refused if an agent runs the terminal
  • Apply: re-checks the file hash, keeps a backup, writes atomically

There is no MCP tool for approve or apply. The approval is bound to one exact diff and one version of the file.
